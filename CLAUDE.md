# Demo — портфолио демо-сайтов (репозиторий moshrell/demo)

Один проект = одна папка в корне (`architekt/`, ...). Новый проект создаётся из `_template/` (Astro). Свои скиллы в `.claude/skills/`: `demo-site-workflow`, `client-brief`, `scroll-bake-hero`. Сторонние `hallmark` и `firecrawl-website-design-clone` в репозиторий не коммитятся (публичный репозиторий, `.gitignore`): оригиналы лежат в `D:\Webdesign\.claude\skills\`; когда нужны в облачной сессии, достать оттуда через device_stage_files (по файлам или одним tar) и положить в `.claude/skills/`.

Папка `_template` и папки, начинающиеся с `_`, на GitHub Pages не публикуются.

## Как работать со Степаном
- Язык: русский. Кратко, структурно, без воды и без «сделать ли?»: сразу результат и решения.
- Любое немецкое слово/фразу сразу переводить: он видит их впервые.
- Скриншоты не делать без явной просьбы. Проверять кодом и числами; визуальные замечания он присылает сам.
- Не говорить «не могу»: запросить доступ, скачать, запустить. Если шаг требует его действия, сказать, спросить и ждать.
- Концепт и структура под нишу → код → самопроверка по брифу. Первый черновик не показывать.
- Каждое демо отличается структурой страницы, а не только цветом. Палитра, шрифты, сетка и механика у каждого свои; предыдущие демо не эталон стиля.
- Разведка перед концептом: посмотреть 3–4 реальных сайта ниши, зафиксировать, что у них есть, чего нет, что раздражает на телефоне.
- Mobile first (сначала 360–390px). Сайт должен работать безупречно и быстро на телефоне; выбирать надёжное решение, а не рискованную идею.
- Сначала логика пользователя, потом скелет: сайт полезен посетителю (услуги, цены, путь к записи/запросу), а не только красив.
- Известные недочёты кладутся в README папки проекта; Степану сообщать только развилки, где нужно его решение. README держать актуальным (править на месте, чистить устаревшее).
- Результаты сохранять в репозиторий сразу по мере готовности. Коммитить свободно: незакоммиченное в проектах — всегда работа Claude.
- Старые неиспользуемые файлы и ассеты в проектах удалять можно без вопросов.
- Вымышленные имена бюро/людей/салонов проверять веб-поиском на совпадение с реальными (имя + город + ниша) до использования в коде, тексте и промптах. Люди в промптах для Gemini: одетые, нейтральные, без откровенных поз.
- Пути на его компьютере давать в виде `D:\Webdesign\...`.

## Жёсткие границы
- Реальный бизнес, его логотип и фото в демо — только с письменного разрешения. Демо-бизнесы вымышленные и помечены как демо.
- Данные клиента не выдумывать: пробел = `TODO` в коде и в отчёте.
- В публичном репозитории не хранить реальные личные данные Степана (телефон, адрес и т.п.) и данные клиентов.

## Технические договорённости
- Стек: Astro, данные в `src/data/*.json`, шрифты локально (`@fontsource*`), без внешних запросов и трекеров (DSGVO).
- Просмотр с телефона: GitHub Pages. Workflow `.github/workflows/pages.yml` собирает каждую папку с `astro.config.mjs` с `DEMO_BASE=/demo/<папка>/` и публикует на `https://moshrell.github.io/demo/<папка>/`. Все URL ресурсов — через `import.meta.env.BASE_URL`.
- Публикация на основной сайт (`npm run publish` → kravets-site) делается на компьютере Степана, не здесь.
- Node/npm на компьютере Степана из облака не запускать (Linux-бинарники испортят `node_modules`); сборку и проверки делать в облачной копии.

## Картинки (только промпты)
Фото сам не генерирую (Gemini API не использовать). Для сайта с фото кладу в папку проекта `PROMPTS.txt`:
1. Список кадров под нишу и единый стиль кадров. Без заглушек и повторов одного изображения.
2. Каждый промпт полный (весь текст целиком, не из двух частей), по порядку; в заголовке имя файла (jpg) и формат. Формат файла .txt. Референсы не прикреплять: Степан продолжает в том же чате Gemini.
3. Кнопки форматов в Gemini: 1:1, 9:16, 16:9, 3:4, 4:3. Кнопок 4:5 и 3:2 нет.
4. Файлы подключаю в коде по заявленным именам (`<img>`, alt, width/height). Степан кладёт готовые файлы в `public/img/` проекта.
Реальных людей и бренды в промптах не использовать; на фото нет текста и логотипов.

## Формы и данные (всегда)
Готовый блок: `_template/src/components/OrderForm.astro` + `DatenschutzForm.astro`.
1. У каждого поля `label`, placeholder-пример (`Vor- und Nachname`, `z. B. 030 23125 123`, `name@example.com`), `autocomplete`, `type`/`inputmode`.
2. Если собираются имя/телефон/e-mail: обязательный чекбокс согласия со ссылкой на `datenschutz/` этого же демо, сообщение об ошибке, раздел про форму на странице Datenschutz с пометкой «Demo: ничего не отправляется и не хранится».
3. Где есть цены/выбор: «Summe» (итог) виден по ходу выбора (на мобильном липкая плашка) и повторяется в подтверждении.
4. Данные не пропадают никогда: sessionStorage-автосохранение (уже в `OrderForm.astro`), ссылки на Datenschutz/Impressum открываются в новой вкладке, согласие не восстанавливается, очистка после отправки.

Подробности процесса: `.claude/skills/demo-site-workflow/SKILL.md` (часть про пути `D:\Webdesign` и kravets-site относится к компьютеру Степана).
