# STYLE.md — как делаем линейные кодовые видео (Linienfilm)

Это рабочий гайд для меня и на будущее. Источник принципов: разбор репозитория `mexicat/pdoom-video` (README, TREATMENT, ENGINE). Берём **правила и метод**, не внешний вид. Любой новый фильм обязан выглядеть иначе, чем pdoom и чем наши прошлые фильмы.

## 0. Что запрещено копировать из pdoom
- Тёмный фон «ink + bone», оранжевую искру-«сигнал» и сам приём «одна искра проходит через всё».
- Сюжет «трактат из пластин с подписями FIG.», вставки логов, штампы, probability bars.
- Палитру, шрифты (Archivo/Plex/Cormorant), структуру «каждая пластина = свой жанр гравюры».
- Всё, что узнаётся как их кадр. Проверка перед сдачей: «если положить рядом, скажут ли, что это тот же фильм?» Если да, переделать.

## 1. Принципы, которые берём (метод)
1. **Кадр = чистая функция времени.** `render(t)` не использует `Math.random()`, `Date.now()`, накопление состояния. Случайность только через seed. Следствия: превью и экспорт идентичны, перемотка бесплатная, можно рендерить любой кадр отдельно.
2. **Стиль-библия до сцен.** Палитра, толщины линий, список запретов, сетка ритма фиксируются заранее и не нарушаются в процессе.
3. **Цвет — бюджет.** Линейный акт почти бесцветный; единственный цвет — нить (см. п. 4). Большой цвет приберегаем для финала. Один раз потраченный, он не возвращается раньше времени.
4. **Нить.** Одна сквозная визуальная деталь, которая ведёт глаз через все акты и в конце становится смыслом финала.
5. **Ритм на сетке.** Фиксированный BPM, акты = целое число тактов, удары и смены кадра на долях. Движение: резкое ускорение, пауза, щелчок. Сильные кривые (outExpo, inOutCubic, пружина), никаких «плавающих скринсейверов».
6. **Каждый акт — своя механика, общий язык.** Меняется то, что происходит (рисуется, едет, замирает, зажигается), но линия, палитра и бумага общие.
7. **Мелочи ремесла:** motion blur из нескольких суб-кадров на быстром движении, тонкое зерно бумаги, свет только там, где он «горит», все линии на одной сетке толщин.
8. **Проверка перед показом:** числовые проверки + контактный лист для Степана. Без скриншотов с моей стороны (правило Степана).

## 2. Библия стиля фильма «Bay» (BMW-купе в гараже)

### Формат
- **9:16, логика 1080×1920**, mobile first. Рендер: 720×1280 (черновик), 1080×1920 (финал).
- Безопасные зоны: поля 64 px по бокам. Машина стоит в верхних ~60% кадра, нижние ~40% = пустой пол/дорога под шторку и кнопки.
- Длительность **12 с** = 6 тактов по 2 с (120 BPM, доля 0,5 с). Автозапуск один раз + кнопка «Überspringen». Не привязан к скроллу.

### Акты (в тактах)
| Такт | Время | Акт | Что происходит |
|---|---|---|---|
| 1–2 | 0–4 с | **Чертёж** | Перо рисует линию дороги, небоскрёбы, средний план, гараж, затем машину |
| 3–4 | 4–8 с | **Въезд** | Камера подъезжает (zoom 0,48 → 0,96), машина катится в гараж, фары-нить тянутся вперёд, посадка на тормозе |
| 5 | 8–10 с | **Пауза** | Ворота гаража закрываются (рольставни), всё замирает на линиях |
| 6 | 10–12 с | **Свет** | Цвет и свет заливают гараж, нить становится светом. Последний кадр = фон сцены сайта |

### Палитра (одна, не менять)
| Роль | Hex | Где |
|---|---|---|
| paper | `#ECE8DF` | фон линейной фазы |
| ink | `#17181C` | основные линии |
| graphite | `#6B6A68` | второстепенные линии, штриховка |
| thread | `#FF2E6E` | нить: перо, лучи фар, потом свет гаража |
| финальные цвета | задаются в акте «Свет», до него не используются | |

Правило: до такта 6 в кадре кроме paper/ink/graphite может быть **только thread** и только мелко (точка пера, тонкие лучи).

### Линии
- Основная 3 px (экран), второстепенная 1.6 px, штриховка 1 px при alpha ≤ .35. Толщина в **экранных пикселях**: при зуме не меняется.
- Только прямые, дуги, окружности и простые кривые Безье. Окна, панели, шкафы — прямоугольники.
- Здания закрашиваются цветом бумаги (закрывают то, что за ними). Это даёт чистую глубину без оттенков.
- Параллакс только по X, без масштабирования слоёв по глубине (иначе земля «плывёт»).

### Машина
- Обобщённое спорт-купе (профиль, как BMW-купе начала 2000-х по пропорциям), **без почек, эмблем, шильдиков, номера**. Это и юридически чище, и не привязывает демо к бренду.
- Масштаб 190 px/м. Колёса вращаются по пройденному пути (угол = путь / радиус). Нос приседает при торможении (питч от ускорения), после остановки пружина.

### Запреты
Неон-«кибер» заранее, свечение «везде», частицы-туман, градиентные фоны в линейной фазе, эффекты ради эффекта, внешние логотипы, текст на картинке (он живёт на сайте), звук.

## 3. Как собираем (пайплайн)
1. `src/lib.js` — easing, матрицы, построитель путей с частичной отрисовкой по длине, seed-random.
2. `src/scene.js` — вся сцена, один `render(ctx, t)`.
3. `index.html` — превью с таймлайном: `space` пауза, `←/→` ±0,5 с, `,`/`.` покадрово, `[`/`]` по тактам, `?t=3.2`, `?scale=0.5`.
4. `scripts/render.mjs` — Playwright (Chromium headless) → кадры → ffmpeg. Режимы: `video`, `sheet` (контактный лист), `check` (числовые проверки).
5. Проверка: `check` (кадры не пустые, перо в границах, машина в нужной точке, нет NaN), `sheet` — для Степана.

## 4. Как это встроится в сайт (чтобы задумка не ломалась)
- Тот же `scene.js` может работать **живьём на `<canvas>`** (≈30 КБ вместо 5–15 МБ видео, чёткий в любом размере, последний кадр = фон сцены без шва).
- Постер = кадр 0 (бумага + перо), `stage.png` = последний кадр (цветной).
- `prefers-reduced-motion` и «без JS»: сразу показывается `stage.png`.
- Если нужен именно файл: mp4 (iOS) + webm; та же длительность, тот же последний кадр.
